## 教材內容

### Agent 是什麼？主要 Agent 與子 Agent

在 OpenCode 裡，一個 Agent＝一段 System Prompt＋偏好的模型＋權限規則＋名稱與說明，就像一位有固定職責的助手。
主要 Agent（primary）是直接跟你對話的那位，例如 Build 與 Plan；終端機版用 Shift+Tab 或 /agents 切換。
子 Agent（subagent）由主要 Agent 派出去做事，例如 Explore 去搜尋資料。子 Agent 在乾淨的新對話中工作，做完把結果交回來，不會塞滿主對話。
你只要用白話說「請用 reviewer 子 Agent 檢查我的修改」，主要 Agent 就會派它出動。

### 用一個 Markdown 檔建立自訂 Agent

在專案建立 .opencode/agents/ 資料夾，新增 reviewer.md，檔名就是 Agent 的名稱；想讓所有專案都能用，就放在 ~/.config/opencode/agents/。
檔案開頭用 --- 包住的設定區（frontmatter）常用欄位：
description：這個 Agent 做什麼。子 Agent 一定要寫，主要 Agent 靠它決定要派誰。
mode：primary、subagent 或 all（兩者皆可），沒寫時預設為 primary。
model：指定模型，格式為「供應商/模型」，例如 opencode/big-pickle；沒寫時沿用目前對話的模型。
steps：最多執行幾步，避免 AI 停不下來。
設定區下面的內文，就是這個 Agent 的 System Prompt。

### 權限：讓 Agent 只做該做的事

permissions 是一串規則，每條有三個欄位：action（動作，如 edit 修改檔案、shell 執行指令、read 讀檔、webfetch 讀網頁）、resource（對象，可用 * 代表全部）、effect（allow 允許、ask 每次詢問、deny 禁止）。
重要觀念：符合的規則中「最後一條」生效，所以先寫大範圍規則，再寫例外。
例如審稿 Agent 只需要讀，就把 edit 與 shell 設為 deny，它就算想改檔案也做不到。
注意：網路上 OpenCode 1 的舊教學使用 tools、permission、prompt 等欄位，2 代新設定請改用本島的寫法。

## 教材提示詞

### 子 Agent 範本：.opencode/agents/reviewer.md（只讀不改的審稿員）

```text
---
description: 檢查文件的錯字、事實疑點與語意不清之處，只回報不修改
mode: subagent
permissions:
  - action: edit
    resource: "*"
    effect: deny
  - action: shell
    resource: "*"
    effect: deny
---

你是一位細心的審稿員。請檢查指定的文件，依嚴重程度列出問題：
1. 可能錯誤的事實或數字（標示「需查證」）
2. 語意不清、容易誤會的句子（附建議改法）
3. 錯字與標點

每個問題請註明檔名與段落。不要修改任何檔案。
```

### 呼叫子 Agent

```text
請用 reviewer 子 Agent 檢查 notes/ 資料夾裡今天新增的講義，整理成一份問題清單給我。
```

### 主要 Agent 範本：.opencode/agents/writer.md（寫作夥伴）

```text
---
description: 依專案規則撰寫與改寫講義
mode: primary
steps: 20
permissions:
  - action: shell
    resource: "*"
    effect: ask
---

你是一位擅長把技術概念寫得平易近人的講義作者。
- 使用繁體中文（台灣用語），每段不超過 4 句
- 每完成一份講義，最後列出「本次修改的檔案」
- 不確定的內容標示「待查證」，不要自行編造
```
