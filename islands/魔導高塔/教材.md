## 教材內容

### Agent＝模型＋Harness

Harness 原意是馬具：模型是馬，力量很大；Harness 是韁繩、馬鞍與路線，決定這股力量能不能用在對的地方。
在 AI Agent 裡，Harness 指模型以外的一切：System Prompt、專案規則、可用工具、權限、上下文管理、子 Agent，以及檢查結果的回饋機制。
同一個模型放在不同的 Harness 裡，表現可能差很多。這也是 2026 年 AI 圈最常討論的主題：從「怎麼問」（提示詞工程）、「給它看什麼」（上下文工程），進化到「設計整套環境」（Harness 工程）。

### 拆解 OpenCode 的 Harness

依官方文件，OpenCode 每次送給模型的指示依序組合：① Agent（或模型供應商）的 System Prompt → ② 程式模式的工具說明（有啟用時）→ ③ MCP、參考資料與 Skill 的說明 → ④ 全域與專案的 AGENTS.md，以及設定中的 instructions → ⑤ 日期與環境資訊。這些是「合併」而不是互相覆蓋。
接著進入 Agent 迴圈：模型決定要用哪個工具 → OpenCode 先檢查權限（allow／ask／deny）→ 執行並把結果交回模型 → 模型決定下一步，直到完成或達到 steps 上限。
對話快塞滿模型的上下文時，OpenCode 會自動壓縮（compaction）：把較早的對話整理成摘要，並保留最近一段原文，讓工作能繼續。子 Agent 則在全新的上下文中工作，避免主對話被細節淹沒。
你在前幾座島學到的 AGENTS.md、Skill、MCP、自訂 Agent 與權限，全都是在調整這套 Harness。

### 兩種控制：事前引導與事後檢查

好的 Harness 同時有兩種控制：
事前引導（feedforward）：在 AI 動手前告訴它怎麼做，例如 System Prompt、AGENTS.md、Skill、範本。
事後檢查（feedback）：在 AI 做完後驗證結果，例如執行測試或檢查指令、讓只讀的 reviewer 子 Agent 審查、列出修改清單給人確認。
只有引導沒有檢查，錯誤會悄悄溜過；只有檢查沒有引導，AI 會一直重複犯同樣的錯。
核心習慣：AI 每犯一次錯，不只是叫它改，而是問「要加哪一條規則或哪一個檢查，下次就不會再發生？」然後把它寫進 Harness。

### 實作：組出你的迷你 Harness

把前幾課的元件組合起來：
1. AGENTS.md 寫清楚「完成標準」與「完成前檢查」（事前引導）。
2. 建立只讀的 reviewer 子 Agent，用權限禁止它修改檔案（事後檢查）。
3. 建立 /ship 自訂指令，固定「計畫 → 執行 → 審查 → 修正 → 回報」的流程。
4. 在 opencode.jsonc 設定全域權限：執行指令前先詢問、禁止推送到遠端、存取專案外的資料夾要詢問（安全護欄）。
先用免費模型跑一次，觀察哪裡出錯，再回頭調整規則或檢查。這個「觀察 → 調整 Harness → 再試」的循環，就是 Harness 工程的日常。

## 教材提示詞

### 自訂指令：.opencode/commands/ship.md（固定工作流程）

```text
---
description: 標準流程：計畫 → 執行 → 審查 → 修正 → 回報
---

任務：$ARGUMENTS

請依照以下流程完成：
1. 計畫：列出步驟與「完成標準」，先停下來等我確認。
2. 執行：依照 AGENTS.md 的規則完成任務。
3. 審查：請 reviewer 子 Agent 檢查這次的修改。
4. 修正：處理審查提出的問題；無法處理的列為「待決定」。
5. 回報：列出修改的檔案、完成標準是否全部達成，以及建議我人工確認的地方。
```

### 全域安全護欄：opencode.jsonc

```text
{
  "$schema": "https://opencode.ai/config.json",
  "permissions": [
    { "action": "shell", "resource": "*", "effect": "ask" },
    { "action": "shell", "resource": "git status *", "effect": "allow" },
    { "action": "shell", "resource": "git diff *", "effect": "allow" },
    { "action": "shell", "resource": "git push *", "effect": "deny" },
    { "action": "external_directory", "resource": "*", "effect": "ask" }
  ]
}
```

### AGENTS.md 加入回饋迴圈

```text
# 完成標準
- 每個需求都有對應的修改，並列在回報中
- 不確定的內容標示「待查證」

# 完成前檢查（每次都要做）
1. 重新閱讀需求，逐條確認是否完成
2. 有可以執行的檢查（例如測試、格式檢查）就執行，失敗要修正後重跑
3. 大型修改完成後，請 reviewer 子 Agent 審查

# 犯錯紀錄（每次出錯後新增一條規則）
- 範例：不要修改 raw/ 資料夾，只能讀取
```
