1. 咒語入門島

L1 入門｜用 Gemini 免費版學會好好提問

學習目標：能用「角色、任務、背景、限制、格式」五要素寫出具體提問，並追問與查證 AI 的回答。

零成本開始：只要一個 Google 帳號

打開 gemini.google.com（或手機 Gemini App），用 Google 帳號登入就能免費使用。免費版可以聊天、上傳圖片或檔案請它說明，也能用 Canvas 一起編寫文件。 免費版有使用量上限，忙碌時段較強的模型或深入研究等功能可能被限制；額度與模型名稱會依 Google 調整，以畫面顯示為準。 本課程只使用免費功能；遇到需要付費方案的功能（例如 Gemini Spark、Skills、Workspace Studio 自動化），後面的課程改用免費的 OpenCode 完成。

提問五要素：角色、任務、背景、限制、格式

AI 不知道你腦中的情境，資訊給得越具體，結果越貼近需求。 把提問拆成五個要素：角色（用什麼身分回答）、任務（要做什麼）、背景（對象與目的）、限制（字數、語氣、禁止事項）、格式（表格、條列、步驟）。 不必每次五項都寫滿；先寫任務，再補上最影響結果的一兩項，就會明顯進步。

追問、改寫與查證

第一次的回答很少完美，請把對話當成來回修改：「第 2 點再具體一點」、「改成給新手看的語氣」、「整理成表格」。 請它「先問我 3 個問題再回答」，可以讓 AI 補齊它缺少的資訊。 AI 可能把錯的事說得很肯定，數字、日期、法規與引用來源一定要自己查證；個資、公司機密與帳號密碼不要貼進免費服務。

提問要素要交代什麼範例
角色希望 AI 用什麼身分回答你是一位擅長簡報的顧問
任務要它做什麼（動詞開頭）幫我列出 5 頁簡報大綱
背景對象、目的、已知資訊聽眾是第一次接觸 AI 的同事
限制字數、語氣、不能做的事每頁不超過 3 點，避免專有名詞
格式希望產出的樣子用表格呈現：頁次｜標題｜重點

2. 魔法書之島

L2 基礎｜System Prompt：替 AI 設定固定的身分與規則

學習目標：能分辨 System Prompt 與一般提問，並在 Google AI Studio 寫出、測試、修正一份系統提示詞。

什麼是 System Prompt？

每次和 AI 對話時，除了你輸入的問題，背後通常還有一段你看不到的「系統提示詞」，先告訴模型：你是誰、要遵守什麼規則、用什麼格式回答。 它就像員工的工作說明書，整段對話都有效；你的提問則像主管當天交辦的任務。 幾乎所有 AI 產品都靠 System Prompt 決定個性與能力，下一階段的 OpenCode 自訂 Agent，本質上也是「一段 System Prompt＋可用的工具」。

免費實作：在 Google AI Studio 設定系統指令

1. 用 Google 帳號登入 aistudio.google.com（免費，不需信用卡）。 2. 開一個新的 Chat，找到「System instructions（系統指令）」欄位，貼上本島下方的範本並修改括號內容。 3. 在下方對話框用幾個不同問題測試，看 AI 是否一直遵守你的規則。 4. 不滿意就回去改系統指令，再用同樣的問題重測，比較前後差異。 提醒：Google 可能使用免費服務中的對話內容改善產品，練習時請勿貼上個資或機密資料。

好的 System Prompt 長什麼樣？

建議依序寫：身分（你是誰）→ 目標（幫誰解決什麼）→ 規則（必須做／不可以做）→ 輸出格式 → 資訊不足時怎麼辦（例如先發問，不要亂猜）→ 一個示範例子。 寫具體行為，不寫空泛形容詞：「每次回答不超過 5 點」比「回答要精簡」更有效。 規則太多會互相衝突，模型也可能漏掉；先寫最重要的 3～5 條，測試後再補。 想看真實產品的寫法，可以到 OpenCode 的 GitHub 原始碼閱讀它內建的 System Prompt。

誰寫設計 AI 工具的人使用 AI 的人
作用時間整段對話都有效只影響這一輪

3. 魔杖工坊

L3 上手｜安裝 OpenCode，免帳號使用免費 AI 模型

學習目標：能安裝 OpenCode、選擇免費模型，在練習資料夾完成第一個任務，並會用 Plan／Build 與復原功能。

OpenCode 是什麼？

OpenCode 是開源（MIT 授權）的 AI Agent。和聊天機器人不同，它能在你指定的資料夾裡讀檔、建立與修改檔案、執行指令，幫你「動手做完」一件事。 它有桌面版 App、終端機版與網頁介面，軟體本身免費，而且內建一組不需要註冊帳號就能用的免費模型。 目前最新為 OpenCode 2（V2），本島內容依 2026 年 11 月官方文件整理。

安裝：最簡單的是桌面版

新手推薦桌面版：到 opencode.ai/download 下載 OpenCode Desktop（macOS、Windows、Linux 皆有），像一般軟體一樣安裝。Windows 若開啟後一片空白，請安裝或更新 Microsoft Edge WebView2 Runtime。 習慣終端機的人可改裝終端機版： macOS／Linux：curl -fsSL https://opencode.ai/v2/install | bash 已安裝 Node.js：npm install -g @opencode/cli 安裝後在終端機輸入 opencode 即可啟動。

選擇免費模型與注意事項

不用登入就能在模型選單（終端機版輸入 /models）選到 OpenCode 的免費模型，例如 Big Pickle，以及名稱帶「Free」的模型，如 DeepSeek V4.1 Flash Free、GLM-5.3-Flash Free、MiMo-V2.6-Flash Free、Nemotron 3.5 Lightning Free（2026/11/03 官方清單）。 免費模型都是「限時」提供，名單常更換，以模型選單為準；大家共用流量，尖峰時可能暫時無法使用，換一個模型即可。 隱私：官方說明 GLM-5.3-Flash Free 與 DeepSeek V4.1 Flash Free 的供應商不保留資料、不拿來訓練；Big Pickle、MiMo 等模型在免費期間可能使用資料改進模型；Nemotron 系列為 NVIDIA 試用端點，請勿輸入個資或機密。 想用 Gemini：到 Google AI Studio 免費建立 API 金鑰，在 OpenCode 輸入 /connect 選擇 Google 並貼上金鑰（金鑰不要分享或上傳到網路）。

第一個任務：Plan 先想，Build 再做

1. 先建立一個空的練習資料夾（例如桌面上的 ai-practice），用 OpenCode 開啟它。不要一開始就開重要資料夾。 2. 切到 Plan（計畫）Agent：它只規劃、不修改檔案。描述需求，例如「做一個自我介紹網頁」，先看它的計畫。 3. 計畫沒問題，再切回 Build（建置）Agent 請它動手。終端機版按 Shift+Tab 切換 Agent，或輸入 /agents 選擇。 4. 結果不滿意，輸入 /undo 復原上一輪的修改，調整說法後再試。

4. 契約之島

L4 規則｜AGENTS.md 與自訂指令：讓 AI 記住你的做事方法

學習目標：能用 /init 建立 AGENTS.md、寫出精簡有效的專案規則，並把常用提問做成自訂斜線指令。

AGENTS.md：專案的長期記憶

每次開新對話，AI 都會忘記上次你交代的事。AGENTS.md 是放在資料夾裡的說明檔，OpenCode 每次工作前都會自動讀取，等於專案專屬的 System Prompt。 最快的建立方式：在 OpenCode 輸入 /init，它會先閱讀資料夾內容，再引導你建立或更新 AGENTS.md。 OpenCode 2 只認得 AGENTS.md 這個檔名；對話進行中修改它，下一次送出提問前就會自動套用。

寫什麼？越精簡越有效

判斷標準：「沒寫的話，AI 很可能會做錯嗎？」會，才寫進去；AI 本來就會的常識不用寫。 建議內容：這個專案在做什麼、資料夾怎麼分、輸出的語言與風格、完成後要怎麼檢查、絕對不能動的檔案。 全域檔（~/.config/opencode/AGENTS.md）放所有專案都適用的個人偏好；專案根目錄放整個專案的規則；子資料夾再放更細的規則。多個檔案會合併使用，請避免互相矛盾。 如果專案用 Git 管理，記得把 AGENTS.md 一起提交，團隊成員就會拿到同一套規則。

自訂指令：把常用提問變成 /按鈕

L5 進階｜打造專屬 Agent：System Prompt＋模型＋權限

學習目標：能分辨主要 Agent 與子 Agent，用一個 Markdown 檔建立自訂 Agent，並用權限規則限制它能做的事。

Agent 是什麼？主要 Agent 與子 Agent

在 OpenCode 裡，一個 Agent＝一段 System Prompt＋偏好的模型＋權限規則＋名稱與說明，就像一位有固定職責的助手。 主要 Agent（primary）是直接跟你對話的那位，例如 Build 與 Plan；終端機版用 Shift+Tab 或 /agents 切換。 子 Agent（subagent）由主要 Agent 派出去做事，例如 Explore 去搜尋資料。子 Agent 在乾淨的新對話中工作，做完把結果交回來，不會塞滿主對話。 你只要用白話說「請用 reviewer 子 Agent 檢查我的修改」，主要 Agent 就會派它出動。

用一個 Markdown 檔建立自訂 Agent

在專案建立 .opencode/agents/ 資料夾，新增 reviewer.md，檔名就是 Agent 的名稱；想讓所有專案都能用，就放在 ~/.config/opencode/agents/。 檔案開頭用 --- 包住的設定區（frontmatter）常用欄位： description：這個 Agent 做什麼。子 Agent 一定要寫，主要 Agent 靠它決定要派誰。 mode：primary、subagent 或 all（兩者皆可），沒寫時預設為 primary。 model：指定模型，格式為「供應商/模型」，例如 opencode/big-pickle；沒寫時沿用目前對話的模型。 steps：最多執行幾步，避免 AI 停不下來。 設定區下面的內文，就是這個 Agent 的 System Prompt。

權限：讓 Agent 只做該做的事

permissions 是一串規則，每條有三個欄位：action（動作，如 edit 修改檔案、shell 執行指令、read 讀檔、webfetch 讀網頁）、resource（對象，可用 * 代表全部）、effect（allow 允許、ask 每次詢問、deny 禁止）。 重要觀念：符合的規則中「最後一條」生效，所以先寫大範圍規則，再寫例外。 例如審稿 Agent 只需要讀，就把 edit 與 shell 設為 deny，它就算想改檔案也做不到。 注意：網路上 OpenCode 1 的舊教學使用 tools、permission、prompt 等欄位，2 代新設定請改用本島的寫法。

內建 Agent類型用途
Build主要（primary）預設的工作 Agent，可以修改檔案、執行指令
Plan主要（primary）只探索與規劃，不修改一般專案檔案
General子 Agent（subagent）處理研究與多步驟工作，不能再派出子 Agent
Explore子 Agent（subagent）搜尋、閱讀檔案或網頁，不修改檔案

Skill：需要時才打開的技能包

Skill 是一個資料夾，裡面最重要的是 SKILL.md，寫著「某一類任務該怎麼做」，旁邊還能放範本、參考資料與腳本。 它跟 AGENTS.md 最大的差別：AGENTS.md 每次都會載入；Skill 平時只讓 AI 看到名稱和描述，遇到相關任務才把完整內容載入，不會白白占用 AI 的注意力（上下文）。 在 Gemini 裡 Skills 需要付費方案，在 OpenCode 則免費就能使用。

建立第一個 Skill

1. 在專案建立 .opencode/skills/meeting-notes/ 資料夾（資料夾名稱就是技能 ID，建議用小寫英文加連字號）。 2. 在裡面新增 SKILL.md，開頭寫 name（顯示名稱）與 description（什麼時候該用）。沒有 description 的技能不會被 AI 發現，所以一定要寫清楚。 3. 內文寫步驟，需要時引用同資料夾內的範本檔，例如 templates/notes.md。 放在 ~/.config/opencode/skills/ 則所有專案都能用；OpenCode 也會讀取 .claude/skills 與 .agents/skills，其他 AI 工具的技能包可以直接共用。 不想讓 AI 自動使用、只想手動指定時，在設定區加上 disable-model-invocation: true。

MCP（Model Context Protocol）是讓 AI 連接外部服務的共通標準，像是替 AI 裝上 USB 插座：接上不同的 MCP 伺服器，AI 就多了查文件、讀資料庫、操作雲端服務等工具。 用一行指令就能加入，例如提供最新技術文件查詢的 Context7：opencode mcp add context7 --url https://mcp.context7.com/mcp，再用 opencode mcp list 檢查是否顯示 connected。 加上 --global 就是所有專案都能用。若顯示 needs authentication，在 OpenCode 輸入 /mcps 選擇該伺服器登入。 提醒：每個 MCP 工具都會占用 AI 的上下文，只裝需要的；也只安裝來源可信的伺服器，因為它能代替你存取資料。

L7 高階｜Agent＝模型＋Harness：設計讓 AI 穩定做對事的整套系統

學習目標：能說明 Harness 的組成，拆解 OpenCode 如何組合提示詞、工具與權限，並用前幾課的功能組出一套有檢查機制的工作流程。

Agent＝模型＋Harness

Harness 原意是馬具：模型是馬，力量很大；Harness 是韁繩、馬鞍與路線，決定這股力量能不能用在對的地方。 在 AI Agent 裡，Harness 指模型以外的一切：System Prompt、專案規則、可用工具、權限、上下文管理、子 Agent，以及檢查結果的回饋機制。 同一個模型放在不同的 Harness 裡，表現可能差很多。這也是 2026 年 AI 圈最常討論的主題：從「怎麼問」（提示詞工程）、「給它看什麼」（上下文工程），進化到「設計整套環境」（Harness 工程）。

拆解 OpenCode 的 Harness

依官方文件，OpenCode 每次送給模型的指示依序組合：① Agent（或模型供應商）的 System Prompt → ② 程式模式的工具說明（有啟用時）→ ③ MCP、參考資料與 Skill 的說明 → ④ 全域與專案的 AGENTS.md，以及設定中的 instructions → ⑤ 日期與環境資訊。這些是「合併」而不是互相覆蓋。 接著進入 Agent 迴圈：模型決定要用哪個工具 → OpenCode 先檢查權限（allow／ask／deny）→ 執行並把結果交回模型 → 模型決定下一步，直到完成或達到 steps 上限。 對話快塞滿模型的上下文時，OpenCode 會自動壓縮（compaction）：把較早的對話整理成摘要，並保留最近一段原文，讓工作能繼續。子 Agent 則在全新的上下文中工作，避免主對話被細節淹沒。 你在前幾座島學到的 AGENTS.md、Skill、MCP、自訂 Agent 與權限，全都是在調整這套 Harness。

兩種控制：事前引導與事後檢查

好的 Harness 同時有兩種控制： 事前引導（feedforward）：在 AI 動手前告訴它怎麼做，例如 System Prompt、AGENTS.md、Skill、範本。 事後檢查（feedback）：在 AI 做完後驗證結果，例如執行測試或檢查指令、讓只讀的 reviewer 子 Agent 審查、列出修改清單給人確認。 只有引導沒有檢查，錯誤會悄悄溜過；只有檢查沒有引導，AI 會一直重複犯同樣的錯。 核心習慣：AI 每犯一次錯，不只是叫它改，而是問「要加哪一條規則或哪一個檢查，下次就不會再發生？」然後把它寫進 Harness。

實作：組出你的迷你 Harness

把前幾課的元件組合起來： 1. AGENTS.md 寫清楚「完成標準」與「完成前檢查」（事前引導）。 2. 建立只讀的 reviewer 子 Agent，用權限禁止它修改檔案（事後檢查）。 3. 建立 /ship 自訂指令，固定「計畫 → 執行 → 審查 → 修正 → 回報」的流程。 4. 在 opencode.jsonc 設定全域權限：執行指令前先詢問、禁止推送到遠端、存取專案外的資料夾要詢問（安全護欄）。 先用免費模型跑一次，觀察哪裡出錯，再回頭調整規則或檢查。這個「觀察 → 調整 Harness → 再試」的循環，就是 Harness 工程的日常。
